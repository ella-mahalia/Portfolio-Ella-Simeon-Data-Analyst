Demand risk indicator

Demand Risk ≠ Inventory Shortage. The public dataset does not contain stock-on-hand. This project therefore labels unusually high forecast demand as a planning risk signal rather than claiming an inventory shortage.

04 · METHODOLOGY

How the analysis was built

The workflow is designed to demonstrate the full analyst-to-data-scientist process: data modeling, EDA, feature engineering, forecasting, evaluation, and business interpretation.

01

Data integration

Join historical sales with store attributes and weekly economic / markdown features.

02

Data quality

Convert dates, inspect missing markdowns, validate duplicate keys, and preserve holiday flags.

03

EDA

Analyze trend, seasonality, store types, departments, holidays, and volatility.

04

Feature engineering

Create lags, rolling means, calendar features, holiday indicators, and store-level context.

05

Forecasting

Compare a seasonal baseline with machine-learning regressors using chronological validation.

06

Decision layer

Translate forecast deviation into transparent demand-risk signals for planning.

SQL · Store / Department summary
SELECT
    Store,
    Dept,
    SUM(Weekly_Sales) AS Total_Sales,
    AVG(Weekly_Sales) AS Avg_Weekly_Sales,
    COUNT(DISTINCT Date) AS Weeks
FROM sales
GROUP BY Store, Dept
ORDER BY Total_Sales DESC;
Python · Time-series features
df["lag_1"] = group["Weekly_Sales"].shift(1)
df["lag_4"] = group["Weekly_Sales"].shift(4)

df["rolling_4"] = (
    group["Weekly_Sales"]
    .shift(1)
    .rolling(4)
    .mean()
)
